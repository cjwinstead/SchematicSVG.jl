API reference

Drawing functions

SchematicSVG — Module
SchematicSVG

Dependency-free schematic renderer for Jupyter. A schematic is a list of placed primitives (the same information a CircuiTikZ \draw ... to[R] ... line carries), rendered as inline SVG so the drawing is stored inside the .ipynb itself.

Coordinates are in CircuiTikZ units (y points up); the SVG backend flips y.

source
SchematicSVG.ascii_schematic — Function
ascii_schematic(art; elements=(), nodes=Dict(), style=:below, labels=Dict(),
                dx=0.5, dy=0.8, nodelabels=false, kw...) -> Schematic

Turn ASCII art into a schematic (see the legend in the source).

  • elements, nodes, style: annotations, matched to instance and node names in the drawing; see annotate.
  • labels: overrides the default label of any word or node tag, e.g. Dict("R1" => raw"$R_{load}$").
  • nodelabels: true labels every node that doesn't already show a name with its netlist name (n1, n2, …), and :all also labels ground and supplies; see label_nodes.
  • dx/dy: size of a character cell in circuit units. Other keywords go to Schematic, e.g. xscale=1.5 / yscale=0.8 to spread or tighten the layout while symbols and text keep their size.

SchematicSVG.@schem_str — Macro
schem""" … """

ASCII schematic literal: ascii_schematic of the text with default options. Like a raw string, it does no interpolation, so $…$ labels can be written directly. A notebook cell ending in one displays the drawing.

source
SchematicSVG.tikz_schematic — Function
tikz_schematic(src; elements=(), nodes=Dict(), style=:below, nodelabels=false, kw...) -> Schematic

Read CircuiTikZ source (a circuitikz environment, or just its \draw statements) and return a Schematic that displays as SVG. Supports the common subset of CircuiTikZ (see the README); statements it can't read are skipped with a warning. elements, nodes and style add annotations as in annotate; nodelabels=true (or :all) labels the nodes with their netlist names as in label_nodes; other keywords go to Schematic.

Coordinates are taken as cm, so the default scale=50 draws 1 cm as 50 px. The environment's xscale=/yscale= (and these keywords) spread the layout while symbols and text keep their size.

SchematicSVG.@tikz_str — Macro
tikz""" … """

CircuiTikZ literal: tikz_schematic of the code with default options, so a \begin{circuitikz} … \end{circuitikz} block can be pasted as is. Like a raw string, it does no interpolation or escape processing.

SchematicSVG.Schematic — Type
Schematic(items; scale=50, stroke="#222", background="white", font="serif",
          xscale=1, yscale=1, border=true)

A drawing: a list of placed primitives (Bipole, Transistor, Wire, …) and how to render it. It displays as inline SVG in a notebook; to_svg gives the SVG text. ascii_schematic, tikz_schematic, annotate and layout all return one.

  • scale: pixels per circuit unit (it also sizes transistors and op-amps).
  • stroke, background, font: line colour, background colour ("none" for transparent) and label font.
  • xscale, yscale: spread the layout horizontally or vertically (or tighten it, below
    1. while symbols and text keep their size.
  • border: a thick gray frame with rounded corners around the figure, so a drawing that runs past the edge of a notebook window is easy to spot.

values holds the element values the drawing was annotated with, by instance name; the netlisters use them.

source
SchematicSVG.to_svg — Function
to_svg(s::Schematic) -> String

The schematic as a standalone SVG document, for saving to a file or embedding in a web page or a document. Notebooks don't need it: a Schematic displays itself as SVG.

SchematicSVG.layout — Function
layout(parts...; direction=:row, gap=1.5, align=nothing, connect=[], share=[],
       nodelabels=false, compact=true, rails=true, kw...) -> Schematic

Place drawings side by side (direction=:row, left to right) or stacked (direction=:column, top to bottom) in one figure, gap circuit units apart. A part is a Schematic (for instance one annotated with its own values) or an ASCII drawing, which is parsed with ascii_schematic. The result is an ordinary Schematic: it can be annotated, netlisted, turned into a subcircuit or laid out again.

Parts can be joined at their terminals in two ways, which can be mixed:

  • connect=[(1, "out") => (2, "in")] draws the connection: the second part is shifted so the two terminals line up and a wire joins them, replacing both terminal circles. The parts must be neighbours, and each neighbouring pair can have one drawn connection.
  • share=[(1, "out") => (2, "in")] connects by name only: both terminals (or node tags) stay drawn and take one name, so their labels match. A plain name, share=["vb"], makes that node common to every part that has it.

Supplies and ground are always common. Any other element or node name used in more than one part gets the part's number as a suffix in the result (CC1 → CC1_1, CC1_2; @g → g_1, g_2), so separate parts stay separate. The joined node of a drawn connection keeps the first terminal's name (with the part suffix if that name is used elsewhere), and so does a shared pair. Drawn labels of elements are unchanged; terminal and node labels that show their node name follow the renaming.

nodelabels=true labels the nodes of the combined circuit with their netlist names, as label_nodes does (:all also labels ground and supplies). Label the result rather than the parts: a part's labels become node names, numbered like any other name.

In a row, every part's top supplies (VDD, VCC) line up at the top of the figure and its bottom supplies (VSS, VEE) at the bottom, by lengthening the vertical wires that lead to them (rails=false turns this off). Before placing the parts, long runs of vertical wire are shortened to one row (compact=false keeps them): only stretches where nothing but vertical wires cross, so components keep their spacing. Wires of a drawn connection stay straight; a supply that can't move without bending one stays where it is.

align sets how parts not joined by a drawn connection line up: :top (the default for a row), :center or :bottom; for a column :left (the default), :center or :right. Other keywords are settings of the result (xscale, border, …), which otherwise come from the first part.

[s1 s2] and [s1; s2] lay out Schematics in a row or a column with the defaults.

Primitive types

SchematicSVG.Pt — Type
Pt(x, y)

A point in circuit units, with y pointing up (as in CircuiTikZ; the SVG output flips it). Points support +, - and scaling by a number, so Pt(1, 2) + 0.5 * Pt(2, 0) is Pt(2, 2).

source
SchematicSVG.Bipole — Type
Bipole(kind, a, b, label=""; name="", note="", side=:auto)

Two-terminal element drawn along the segment a→b (like CircuiTikZ to[...]). kind ∈ :R, :C, :L, :D, :V, :I, :cV, :cI, :sV (sinusoidal), :box, :open, :short. For sources a is the SPICE n+ terminal ('+' drawn near a; current arrow a→b). name is the instance name used to match annotations; note is a second line of text (value or model). side places the label: :auto (above horizontal parts, right of vertical ones, note stacked/opposite), or :left/:right of the a→b direction like CircuiTikZ l=/l_=, with the note on the other side.

source
SchematicSVG.Transistor — Type
Transistor(kind, name, at; xflip=false, yflip=false, label=name, note="", w=0.5, h=0.5)

Three-terminal device centred at at. kind ∈ :npn, :pnp, :nmos, :pmos. xflip mirrors left/right (control pin on the right); yflip swaps top/bottom. w is the distance from the centre to the gate/base pin and h to the top/bottom pins (circuit units); CircuiTikZ imports use its own dimensions.

source
SchematicSVG.Opamp — Type
Opamp(name, at; label="", note="", w=0.5, h=0.2, inv_up=false)

Op-amp centred at at: inputs on the left at ±h, output on the right, pins w from the centre. The + input is on top unless inv_up (the CircuiTikZ default). Pins :inp, :inn, :out (usable in PinRef).

source
SchematicSVG.Wire — Type
Wire(points...)

A polyline through points, each a Pt or a PinRef. Wire ends and corners that meet other wires, pins or symbols connect to them, as does a point lying on another wire (a T-junction); wires that only cross stay separate. Junction dots are not added automatically for placed drawings: add a Dot.

source
SchematicSVG.PinRef — Type
PinRef(device, pin)

A pin of a named transistor or op-amp, used as a Wire point: PinRef("Q1", :C), PinRef("M1", :G), PinRef("A1", :out). It is resolved when the schematic is drawn or netlisted, so wires follow the device wherever it sits. Transistor pins are :B/:G, :C/:D and :E/:S; op-amp pins :inp, :inn and :out.

source
SchematicSVG.pin — Function
pin(device, p) -> Pt

Position of pin p of a Transistor (:B/:G control, :C/:D top, :E/:S bottom, after any flips) or an op-amp (:inp, :inn, :out), in circuit units.

source
SchematicSVG.Ground — Type
Ground(at, flip=false)

Ground symbol hanging below at (pointing up when flip). Every ground is node 0 in netlists.

source
SchematicSVG.Supply — Type
Supply(at, label, up)

Supply rail: a bar at at with label above it (up=true, e.g. "V_{DD}") or below it (up=false, e.g. "V_{SS}"). The label names the supply node in netlists (V_{DD} → vdd), and supplies with the same name are one node.

source
SchematicSVG.Port — Type
Port(at, label, side; name=label)

Open-circle terminal. side ∈ :left, :right, :above, :below says where the text goes. name is the node name used to match node annotations.

source
SchematicSVG.NodeLabel — Type
NodeLabel(at, name, side; label=name)

Names a node without drawing a terminal: italic text beside the wire point at. side ∈ :left, :right, :above, :below.

source
SchematicSVG.Dot — Type
Dot(at)

Junction dot at at. Purely visual: points connect whether or not a dot is drawn.

source
SchematicSVG.Voltage — Type
Voltage(plus, minus, label=""; side=:right, kind=:open)

Voltage polarity marks, like CircuiTikZ v=: + at the plus end, − at the minus end, and label between them. For an open circuit (kind=:open) the signs sit on the line near its two ends; for a component (kind=:R, :C, …, the kind of the Bipole drawn between the same points) they flank its symbol. side is :right or :left of the plus → minus direction, or :auto (above horizontal parts, right of vertical ones). Voltage marks are annotation only: they don't affect the netlist.

source
SchematicSVG.Current — Type
Current(a, b, label=""; side=:auto, into=false, pos=0.5, kind=:short)

Current arrow on the wire from a toward b, like CircuiTikZ i=: it points at b (back at a when into), with label beside it. To mark the currents branching at a node, give each branch its own arrow with a at the node: Current(node, p, "i_1") is a current leaving the node and into=true one entering it. pos is the arrow's place as a fraction of a → b. When a Bipole of kind kind (:R, :C, …) is drawn between the same points the arrow goes on one of its leads instead: the end lead when pos ≥ 0.5, the start lead otherwise. side is :left or :right of the a → b direction, or :auto (above horizontal wires, right of vertical ones). Current arrows are annotation only: they don't affect the netlist.

source
SchematicSVG.Caption — Type
Caption(at, text; align=:center)

Free text, such as a title under part of a drawing, centred on at (or starting / ending there with align=:left / :right). Plain text is shown as written; text with $…$ uses the same LaTeX subset as labels.

Annotation functions

SchematicSVG.annotate — Function
annotate(s::Schematic, elements=(); nodes=Dict(), style=:below) -> Schematic

Return a copy of s with element values/models and node annotations added.

  • elements: a collection of element objects (see instancename, annotation), or a dictionary name => value. Numbers are printed with SI prefixes and a unit implied by the instance letter (R1 => 4700 → "4.7 kΩ"); anything else is printed as is.
  • nodes: dictionary node => annotation for terminals (vout) and node tags (@vx). A number is appended as a voltage ("vx" => 2.5 → "vx = 2.5 V"); a string replaces the displayed text (label syntax allowed, e.g. raw"$v_x$ = 2.5 V").
  • style: :below puts the value on a second line (opposite side from the name on horizontal parts, under it otherwise); :inline prints "R₁ = 4.7 kΩ" on one line; :value shows the value instead of the name.
source
SchematicSVG.label_nodes — Function
label_nodes(s::Schematic; nodes=:unnamed, rename=Dict()) -> Schematic

A copy of s with every node labelled by its netlist name, so the drawing can be read side by side with spice_netlist(s) or schematic_netlist(s).

By default only the nodes that don't already show a name get a label: the ones the netlist calls n1, n2, …, and the joined nodes of a layout. Terminals and @ node tags already show their names. nodes=:all also labels ground (0) and supply nodes (vdd, …) with their netlist names. rename is the same mapping as for schematic_netlist, so the labels match a netlist written with it.

Each label sits beside the node's longest wire (above a horizontal wire, right of a vertical one), at a spot no other node's wire passes through. ascii_schematic(…; nodelabels=true) and tikz_schematic(…; nodelabels=true) (or nodelabels=:all) do the same as they draw.

si(x, unit="") -> String

Engineering notation with an SI prefix and three significant digits: si(4700, "Ω") == "4.7 kΩ", si(2.2e-9, "F") == "2.2 nF".

Netlist functions

SchematicSVG.schematic_netlist — Function
schematic_netlist(s::Schematic; elements=(), supplies=Dict()) -> SchematicNetlist

Extract the circuit drawn in s: devices with their nodes in SPICE order, and node names. Ground symbols are node "0"; supply symbols, terminals and @ node tags name their nodes (vdd, vin, …); other nodes are numbered n1, n2, ….

Device values are looked up by instance name (case-insensitive) in elements (a collection of element objects or a name => value dictionary, as for annotate), then in the elements the schematic was annotated with, and finally read from the drawing's text. For dependent sources give (gain, control): a pair of node names for E/G sources, a voltage-source name for H/F sources. supplies gives the voltage of each supply net, e.g. Dict("vdd" => 5).

rename maps drawn node names to netlist names, e.g. Dict("vdd" => "vdd!") for global nodes. external lists nodes connected outside the drawing (subcircuit terminals, global supplies): they count as driven for the DC check and need no supply voltage. The symbol :terminals in external stands for every drawn terminal (see SchematicNetlist).

Warns about devices without a value, unconnected pins, nodes with conflicting names, and nodes with no DC path to ground.

source
SchematicSVG.SchematicNetlist — Type
SchematicNetlist

Result of schematic_netlist: devices (a vector of NetDevice), supplies (supply net => value, nothing when not given), nets (all node names; ground is "0") and terminals (the named nodes with a terminal circle, left to right and then top to bottom: the default subcircuit terminals). Displays as SPICE text.

source
SchematicSVG.NetDevice — Type
NetDevice(name, kind, nodes, value)

One device of a SchematicNetlist. kind is one of :R :C :L :D :V :I :sV :sI :E :F :G :H :nmos :pmos :npn :pnp :opamp and nodes are in SPICE order: (n+, n−) for two-terminal parts and sources, (anode, cathode) for diodes, (drain, gate, source), (collector, base, emitter), and (+, −, out) for op-amps. value is whatever was supplied for the device (a number, string, symbol, tuple, NamedTuple or an element object), or what could be read from the drawing, or nothing.

source
SchematicSVG.spice_netlist — Function
spice_netlist(s::Schematic; title="schematic", include=nothing, elements=(), supplies=Dict()) -> String

SPICE text for the circuit drawn in s (see schematic_netlist), with a title line, an optional .include and .end. Values without units are written as plain numbers; devices without a value get a {name} parameter, and parts without a model use the Microelectronics.jl library defaults (D1N914, ald1105n/p, Q2N3904/6, ideal_opamp).

source
SchematicSVG.spice_subcircuit — Function
spice_subcircuit(s::Schematic; name, terminals=nothing, params=(), rename=Dict(), elements=()) -> String

A .subckt name terminals… params: … … .ends block for the circuit drawn in s.

The terminals are the drawn terminals (named nodes with a terminal circle: in, out in an ASCII drawing, or an ocirc with a text label in CircuiTikZ), in order left to right and then top to bottom. Pass terminals (drawn node names, e.g. ["inp", "inn", "outp", "outn"]) to choose them or their order. Supply nodes are left to the enclosing netlist, so use rename to make them global (Dict("vdd" => "vdd!"), with .global vdd! in the netlist). params are name => default pairs that device values can refer to as symbols (:Rload is written {Rload}).

source
SchematicSVG.to_microelectronics — Function
to_microelectronics(s::Schematic; elements=(), supplies=Dict()) -> (; sources, components)

Microelectronics.jl objects for the circuit drawn in s, ready for build_netlist(; to_microelectronics(s)...). Available after using Microelectronics (it is a package extension). Element objects you pass in elements (or annotated the schematic with) are reused with the schematic's nodes, so their values, models, waveforms and parameters carry over; other devices are built from the values found by schematic_netlist.

source
SchematicSVG.to_subcircuit — Function
to_subcircuit(s::Schematic; name, terminals=nothing, parameters=[], rename=Dict(), elements=())

A Microelectronics.jl Subcircuit for the circuit drawn in s. Its terminals are the drawn terminals, left to right and then top to bottom, unless terminals (drawn node names) chooses them or their order; see spice_subcircuit for rename and parameters. Available after using Microelectronics.

source
SchematicSVG.parse_value — Function
parse_value(text) -> Float64 or nothing

Read an engineering value such as "4.7 kΩ", "10µF", "2.2n", "1e3" or "5 V". Prefixes are SI (M is mega, m is milli; "meg" also works). Returns nothing if text isn't a value.
